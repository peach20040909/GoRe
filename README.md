## 1. 문제

**여행자는 장소에 흔적을 남기고 싶어 하지만, 지금의 관광지는 기록을 남길 방법도, 다시 찾아올 이유도 남겨 주지 않는다.**

| # | 문제 | 근거 |
|---|---|---|
| P1 | **남길 방법이 없다.** 물리 매개체는 장소를 해치고, 종이 방명록은 다국어도 보관도 안 된다 | 남산 자물쇠 환경 오염 우려, 파리 퐁데자르 자물쇠 금지(#lovewithoutlocks), 하회마을 한글 낙서 훼손 |
| P2 | **남겨도 다시 올 이유가 되지 않는다.** 장소에는 '나를 기다리는 것'이 없다 | 서울 재방문 의향 90.2%, 방한 재방문율 56.6% |
| P3 | **장소는 누가 왔다 갔는지 모른다.** 서대문 문화 공간은 방문·재방문이 측정되지 않는다 | 서울관광 실태조사 52개 방문지 중 서대문 단독 장소는 독립문(1.9%)뿐. 홍제폭포는 외국인 130만 명이 왔지만 체류·연계 방문은 측정 안 됨 |

**해결책이 넘어야 할 조건:** 외국인 불편 1위는 디지털 진입 장벽(27.8%, 그중 가입·인증 13.1%)이고, 언어소통 만족도는 7개 항목 중 최저(83.0점)다.
→ **가입 없이, 어떤 언어로든** 쓸 수 있어야 한다.

**사용자**
- 1차: 서울을 찾는 외국인 여행자 (첫 방문·장기 체류자, 유럽·미주·대양주·동남아)
- 초기: 서울을 찾은 외국인 부부·커플
- 공급 측: 서울 대표 관광지, 서대문 문화 공간

## 2. 해결: 맡기기 → 잠그기 → 꺼내기

| 문제 | 우리의 답 |
|---|---|
| P1 남길 방법이 없다 | 장소를 해치지 않는 **디지털 매개체**(자물쇠·원고지·봉화·유리병 편지)를 **그 자리에서만** 맡김 |
| P2 다시 올 이유가 없다 | **다시 와야 열리는 타임캡슐** + AI 재회 리포트 |
| P3 장소는 모른다 | 기록이 쌓이며 장소별 방문 언어·재방문율 데이터가 생김 |
| 진입 장벽 | **가입 없는 QR**, 어떤 언어로든 글·음성으로 남기면 AI가 알아서 정리 |

### 핵심 흐름

```
문화 공간 QR → 위치·사진 인증 → 매개체 선택 → 기억 남기기(글·음성)
  → 기억 카드 생성 → 열림 조건 선택 → 타임캡슐 보관
  → (다시 방문) 같은 자리 판정 → 재회 리포트 → 새 기억 한 겹 더 ↺
```

| 단계 | 사용자 | AI |
|---|---|---|
| **맡기기** | QR을 찍고, 매개체를 고르고, 기억을 담는다 | 위치와 사진으로 '그 자리'인지 확인한다. 어떤 언어로 쓰든 말하든 기억을 이해해 기록 유형·대상·감정을 정리한다 |
| **잠그기** | 언제, 어떻게 다시 열지 정한다 | 기억의 내용과 시점을 보고 열림 조건을 제안한다. 기억을 카드로 만든다(사진 해석 + 각인 문구, 내 언어 + 한글) |
| **꺼내기** | 다시 와서 연다 | 같은 자리에 왔는지 판정한다. 그때와 지금을 비교한 재회 리포트를 쓴다 |

챗봇은 없다. 기억은 **한 번에** 남기고, AI는 대화 대신 **이해·생성·판정**을 맡는다.

### 매개체 — 장소마다 다르게, 기본은 자물쇠

| 장소 | 매개체 | 이유 |
|---|---|---|
| 어디서나 (기본) | 자물쇠 | 남산 덕분에 외국인도 바로 이해한다 |
| 윤동주기념관 | 원고지 | 시인이 학생 시절을 보낸 곳. 내 기억을 원고지 한 장에 쓴다 |
| 안산 봉수대 | 봉화 | 산에서 산으로 소식을 전하던 곳. 멀리 있는 사람에게 보내는 기억 |
| 홍제폭포 | 유리병 편지 | 물가이고, 외국인 누적 130만 명이 찾은 SNS 거점 |
| 서대문형무소역사관 | 추모 기록 (엄숙 모드) | 재미 요소를 빼고 감사·추모의 기록만 남긴다 |

### 기록 유형과 운 카테고리

- **기록 유형:** 소원형 · 회고형 · 편지형
- **운 카테고리 (소원형, 3×3):** 연애 · 재물 · 합격·성취 · 건강·평안 · 가족 · 인연 · 재회·소식 · 새출발·용기 · 나만의 운
- **대상:** 나 / 연인 / 가족 / 친구 / 멀리 있는 누군가
- 사용자가 카테고리를 직접 고르지 않아도 AI가 분류한다.

## 3. AI가 핵심 기능이 되는 세 순간

1. **맡기는 순간 — 어떤 언어로 남겨도 AI가 이해한다.** 음성은 글로 옮기고(STT), 기록 유형·운·대상·감정·시점 단서("다음 달 시험")를 구조화한다.
2. **새기는 순간 — 그 시간, 그 자리, 그 마음으로 만드는 기억 카드.** 사진에서 풍경 실루엣·하늘색·계절 단서를 읽고, 기억에서 문양·빛의 세기·각인 문구를 정한다. 같은 기억도 다른 날 다른 자리에서 맡기면 다른 카드가 된다. 그림은 코드(SVG)가 그린다.
3. **꺼내는 순간 — AI가 곧 열쇠.**

| 열림 조건 | AI 판정 |
|---|---|
| 재방문형 | 새 사진이 처음 사진과 같은 자리인지 판정 (+ GPS) |
| 계절형 | 날짜 조건 + 새 사진의 계절 단서 확인 |
| 동행형 | 사진 속 사람이 2명 이상인지 + 같은 장소인지. 얼굴 식별은 하지 않는다(생체정보) |
| 날짜형 | 그날이 되면 열리고, 여는 순간 회고가 시작된다 |

### AI 처리 단계

| 단계 | 이름 | 하는 일 |
|---|---|---|
| A | 장소 인증 | 사진 판정(비전) + GPS 반경 |
| B | 안전 필터 | 유해 표현·저주성 소원 차단, 개인정보 가림 |
| C | 기억 이해 | 유형·운(주·보조)·대상·감정·시점 단서를 구조화 |
| D | 기억 카드 빚기 | 디자인 값(색·모양·문양·빛)과 각인 문구만 정하고, 그림은 코드가 |
| E | 열림 조건 제안 | 날짜형·계절형·재방문형·동행형 중 후보 제안 |
| F | 공개용 한 줄 | 기억 벽에 걸릴 익명 버전. 원문은 본인만 |

호출 구조: **A 사진 판정** ∥ **B 안전 필터** (동시 실행) → **C·D·E·F를 한 번의 호출**로 구조화된 결과 생성

### AI가 없으면?

| 순간 | AI 없이 | AI 있을 때 |
|---|---|---|
| 맡기기 | 정해진 칸을 하나하나 채움 | 어떤 언어로 쓰든 말하든 AI가 이해하고 분류·정리 |
| 새기기 | 정해진 템플릿 | 그날의 풍경·하늘·마음으로 만든 단 하나의 카드 |
| 꺼내기 | 날짜가 되면 자동으로 열림 | 같은 자리·함께 온 사람을 AI가 확인해야 열리고, 그때를 회고 |
| 운영 | 공개 벽을 사람이 검수 | 다국어 필터와 익명화를 자동으로 |

## 4. 재방문을 만드는 장치

- **다시 와야 열림:** 원격으로는 열람할 수 없다.
- **다음 계절에 열림:** "벚꽃 필 때", "첫눈 오는 날". 계절 변화를 재방문 이유로 쓴다.
- **함께 와야 열림:** 새 방문자를 데려오는 장치가 된다.
- **가입 없는 알림:** 계정 대신 캘린더 일정(.ics)으로 저장한다.
- **기록이 자람:** 열 때마다 새 기억을 한 겹 더 쌓아 '나의 서울 연대기'가 된다.

## 5. 문화 공간에 남는 가치

- **장소의 기억 아카이브:** 공개에 동의한 기록이 익명 한 줄로 그 장소의 '기억 벽'이 된다. 홍제폭포 복합문화센터 미디어전시관 같은 곳에서 전시로 이어 갈 수 있다.
- **운영 데이터:** 장소별 방문 언어, 재방문율, 계절별 기록량. 공식 통계에서 측정되지 않는 공백을 채운다.
- **현장 소비:** 기억 카드를 실물 엽서로 인쇄하거나 지역 기념품과 연결한다.

## 6. 기존 서비스와의 차이

| 서비스 | 방식 | 우리와의 차이 |
|---|---|---|
| 디지털 자물쇠 앱 (PADLOVE 등) | 어디서나 가상 자물쇠를 검 | 우리는 그 자리에서만 맡기고, 다시 와야 꺼낸다. AI 판정과 생성이 있다 |
| 오디오가이드 (관광공사 오디) | 장소가 나에게 이야기를 들려줌 | 우리는 내가 장소에 이야기를 남긴다 |
| 종이 방명록 | 적고 끝 | 다시 올 이유가 생기고, 다국어로 읽힌다 |

## 7. 해커톤 MVP 범위

**넣는 것**
- 장소 2~3곳 (홍제폭포 중심)
- 위치·사진 인증, 기억 입력(텍스트·음성, 한 번에)
- 기억 카드 생성 (A~F 처리)
- 열림 조건 선택과 데모 모드(시간 넘기기)
- 다시 열기와 재회 리포트
- 장소별 기억 벽

**빼는 것 (화면 목업만):** 동행 인증, 캘린더 알림 발송, 운영 대시보드, 실물 엽서 인쇄

### 데모 시나리오 (3분)

1. 홍제폭포 표지판 QR을 찍는다. 가입 없이 열리고 브라우저 언어로 표시된다.
2. '유리병 편지'를 고르고, 안내 문구("이 폭포 앞에서, 누구에게 무슨 말을 남기고 싶나요?")를 보며 아무 언어로 쓰거나 말한다. AI가 유형·운·대상을 정리한다.
3. 폭포 사진을 올리면 AI가 장소를 확인하고 기억 카드를 만든다. 그날의 하늘색, 폭포 실루엣, 두 언어 각인 문구가 들어간다.
4. 열림 조건으로 '다음 계절에'를 고른다.
5. 데모 모드로 석 달 뒤로 넘긴다. 겨울 빙벽 사진을 올리면 "같은 자리 확인, 폭포가 얼었네요" 판정과 함께 병이 열리고 재회 리포트가 나온다.
6. 홍제폭포 기억 벽과 운영 대시보드 목업(재방문율·언어 분포)을 보여 준다.

## 8. 리스크와 대응

| 리스크 | 대응 |
|---|---|
| 엄숙한 공간(형무소)에서의 부적절한 톤 | 매개체·문구·연출을 따로 설계하는 엄숙 모드 |
| 개인정보 (원문, 음성, 사진 속 얼굴) | 원문은 본인만 열람, 공개 벽은 익명 한 줄만, 얼굴 자동 흐림 |
| 같은 자리 재인식 오판 | GPS 병행, 판정 기준을 너그럽게 |
| 산 정상 등 약한 신호 | 먼저 기록하고, 신호가 잡히면 생성 |
| 대기 시간 | 호출 3번 구조, 대기 중 '쇠를 두드리는' 연출 |
| 초기에 기록이 없음 | 실제 사람의 기록으로 시작. AI가 쓴 가짜 기록은 넣지 않음 |

## 개발

### 스택

| 영역 | 사용 |
|---|---|
| 웹 | Next.js 15 (App Router) + TypeScript + Tailwind CSS v4, 모바일 우선 |
| AI | OpenAI (`gpt-4o-mini`, 이미지 이해 포함). `src/lib/ai.ts` 한 곳에서 호출, 키가 없거나 실패하면 시연용 예시 응답 |
| DB · 사진 | Supabase (Postgres + Storage). 서버(API 라우트)에서만 접근 |
| 배포 | Vercel — `main`에 push하면 자동 배포 |

### 실행

```bash
npm install
npm run dev
```

http://localhost:3000 에서 확인합니다. 실행 전에 프로젝트 루트에 `.env.local`을 만들고 아래 값을 채웁니다. 키는 깃이나 단톡방에 올리지 말고 개인 메시지로만 주고받습니다.

| 변수 | 설명 |
|---|---|
| `OPENAI_API_KEY` | OpenAI 키 |
| `OPENAI_MODEL` | 기본 `gpt-4o-mini` |
| `SUPABASE_URL` | Supabase 프로젝트 URL |
| `SUPABASE_SERVICE_ROLE_KEY` | 서버 전용 키 (`NEXT_PUBLIC_` 금지) |
| `ADMIN_KEY` | 장소 좌표 등록용 아무 문자열 |

DB는 Supabase SQL Editor에서 [`supabase/schema.sql`](supabase/schema.sql)을 한 번 실행하면 만들어집니다.

### 구조

```
src/
  lib/ai.ts          AI 호출 (OpenAI/Anthropic, 실패 시 mock)
  lib/prompts.ts     AI 프롬프트와 응답 형식
  lib/db.ts          Supabase 호출 헬퍼
  app/api/...        API 라우트 (docs/API.md)
  app/...            화면
supabase/schema.sql  DB 테이블·저장소·장소 초기 데이터
docs/API.md          API 명세와 담당 분배
```

### 협업 규칙

- 작업 브랜치는 `feat/memory-seoul`에서 각자 만든다 (예: `api/db`, `api/ai`).
- 끝나면 `feat/memory-seoul`로 PR → 다 합쳐지면 `main`에 합쳐 배포한다.
- `src/lib/ai.ts`, `src/lib/prompts.ts`는 AI 담당 한 명만 고친다 (충돌 방지).
